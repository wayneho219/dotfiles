# Visual Explainer：互動示意圖學習頁

讀者是**正在學這個主題的初學者**：看不懂專有名詞，也沒辦法自己判斷內容對不對。所以兩件事最重要：**內容要查證**、**每個名詞都要能點開看白話解釋**。

版面：左邊是主題的**實體示意圖**，右邊是**逐步說明面板**。名詞解釋只用「點開跳出」的方式，不要在頁面底部另外列一整份辭典。切換步驟時，示意圖會亮起這一步用到的部分，並用動畫虛線畫出資料流向。

範本：`template.html`（同資料夾，Allwinner A64 開機流程）。**直接複製它再改內容**，不要從零寫起。

## 流程

1. **選一個真實的具體對象**：例如「A64 開機」，不要寫成「一般 ARM 板開機」。只有對象具體，位址、數值、log 才能查證，而且前後一致。
2. **先查證，再寫**：用 WebSearch / WebFetch 查一手來源，把每個關鍵事實（位址、大小、順序、規則、指令輸出格式）都對過一次。
   - 優先順序：官方文件（kernel docs、U-Boot docs、RFC、廠商 datasheet）> 原始碼（dts、header、defconfig）> 社群 wiki > 部落格
   - 查不到的就標「未查證」，不要硬寫成事實
   - 廠商 wiki 擋自動抓取時（例如 wiki.st.com 會逾時），改查 TF-A、U-Boot、Linux 原始碼裡該晶片的 header、defconfig、dts，以及 readthedocs 上的官方文件
   - 查證時發現自己原本的認知錯了，要改正（例如：A64 用 DDR3，不是 DDR4）
3. 呼叫 `Artifact` 的 `action: "quickstart"`（`intent: "other"`）。
4. 決定要畫的「實體」：開機 → 開發板；pointer → 記憶體格子與位址；TCP → 兩台主機與封包；中斷 → CPU、中斷控制器、周邊。畫東西本身，不要畫抽象的流程方塊。
5. 切成 4–8 個步驟，順序本身就是要學的內容。
6. 複製 `template.html` 到 scratchpad，修改以下部分：
   - SVG：零件用 `<g class="part" id="p-xxx" data-term="名詞">`，裡面放一個 `class="body"` 的外框；流向用 `<path class="flow" id="f-xxx" marker-end="url(#ah)">`
   - `GLOSSARY`：步驟文字裡出現的每個專有名詞都要放進來（程式會自動把它們變成可點的詞）
   - `STEPS`：每一步的內容，欄位見下表
7. 發布 Artifact，回覆使用者連結，並列出查證了哪些來源、哪些內容沒查到。

## STEPS 欄位

| 欄位 | 內容 |
|---|---|
| `t` | 這一步的標題 |
| `plain` | **一句話白話版**，不懂任何名詞的人也看得懂 |
| `run` | 主題的「主線狀態」，例如程式在 ROM/SRAM/DRAM、TCP 狀態（CLOSED/SYN_SENT/ESTABLISHED） |
| `seq` | **依序發生的動作**，一般 4–6 條；關鍵步驟要寫出完整路線（可到 10 條以上），每一條都要對應圖上的一個零件，讓使用者滑過時能看到元件。不要另外做「放大看」小圖取代它：`[['零件id', '誰做了什麼']]`。一條只寫一個動作，不寫成段落。滑過某一條時，板子上只亮那個零件 |
| `pts` | 「要記住的」3 點：觀念、面試題、容易搞錯的地方。**不能重複 `seq` 已經講過的動作** |
| `log` | 真實世界會看到的東西：log、指令輸出、程式碼、封包內容。格式要跟真的一樣 |
| `mem` | 這一步的狀態表：記憶體內容、暫存器值、封包欄位…… |
| `stuck` | 這一步出錯時長什麼樣子，代表什麼原因 |
| `src` | `[['ok'或'warn', 說明, 網址]]`。ok＝已查證，warn＝未查證或示意 |

## 寫給初學者的原則

- 全部用繁體中文。
- **不要假設讀者懂任何專有名詞**。只要是縮寫、術語、元件名稱，都放進 `GLOSSARY`：`d` 寫一句白話定義，`e` 寫一個具體例子或比喻，最好是這個主題裡的真實數值。
- 只有中文的名詞，GLOSSARY 裡要加 `en` 欄位寫英文（例如 `'暫存器': { en:'register', d:'…' }`）。頁面會在名詞第一次出現時用灰色小字標出英文，解釋框標題也會中英並列。
- 解釋名詞時，不要用另一個沒解釋的名詞；真的要用，那個名詞也要進辭典。
- 先講「做什麼、為什麼」，再講「怎麼做」。每一步的 `plain` 要讓人不看其他欄位也懂個大概。
- 句子要短，一句只講一件事。
- 頁面打開就要顯示 STEP 0 的完整內容，不能是空的。
- 不要放頁首大標題、說明文字：頁面一打開就是步驟列，標題交給 Artifact 名稱。
- 版面固定：步驟列黏在最上方，示意圖黏在左側步驟列下方，只有右側說明面板會捲動（範本已實作，不要拿掉）。
- 使用者眼睛不好，字要大：保留範本裡「大字版」那段 CSS（內文 20px、標題 32px、程式碼 14.5px、圖內文字 13 以上、方框標題 16），不要縮小。圖內字放大時，要把方框加大、字句縮短，並用估算確認沒有字超出方框。
- 圖的大小固定：SVG viewBox 760×600（寬×高），版面 max-width 1440px、圖欄與說明欄比例 1.25fr：1fr。這個高度在使用者的瀏覽器剛好能一次看到整張圖，不要做得更高；內容放不下就精簡字句或減少方框。
- 支援鍵盤 ← →，並尊重 `prefers-reduced-motion`。
- 淺色、深色主題都要能看，顏色全部用 `:root` token 定義（範本已示範）。
